# Organización conservadora del repositorio — 13/11/2026

Se conservan `apps/web`, `apps/services`, `apps/mobile`, `apps/desktop`, `data`, `documentation` y `stuff`. La arquitectura recomendada en la imagen orienta la separación de responsabilidades; mover carpetas a nombres distintos no mejora por sí mismo esa separación y rompería rutas reproducibles. No se introduce otro frontend ni paquetes compartidos sin consumidores reales.

La inspección encontró cachés y artefactos locales voluminosos, pero también datos, respaldos, evidencia y herramientas bajo `.local`. No se eliminaron datos, evidencia histórica, contratos generados, scripts SQL ni el índice CodeGraph. Los logs versionados pertenecen a evidencia fechada y no se clasifican como basura por extensión.

Se amplió `.dockerignore` para excluir `build`, `dist`, `.gradle`, `.kotlin`, `DerivedData`, `xcuserdata`, `.DS_Store` y caché PyInstaller de todas las aplicaciones. Esto evita enviarlos como contexto de construcción o copiarlos en imágenes mediante COPY de carpetas completas. `.gitignore` ya excluía entornos Python, builds y distribuciones; se añadió la caché específica PyInstaller. No cambia los artefactos seleccionados guardados como evidencia o entrega fuera de esas carpetas.

Verificación: revisión de COPY en Dockerfiles y de los patrones de exclusión; `git diff --check`. No se atribuyen ahorros de bytes o tiempos de construcción sin medir un build Docker real.

Se retiraron dos worktrees temporales concluidos (`redhouse-donor-self-20261113` y `redhouse-transport-context-20261113`). Ambos tenían estado Git limpio, sin `.local` ni entornos Python, y `git cherry entrega-final <rama>` marcó sus únicos commits propios (`a1ea696` y `8dbe694`) como ya aplicados. Se usó `git worktree remove` sin forzar; las ramas y commits permanecen recuperables. Sus tamaños lógicos observados eran 284 y 278 MiB; no se presenta esa suma como ahorro físico medido. Se conservaron SDK, AVD, cachés de compilación, llavero, datos y respaldos; el worktree de seguridad sigue activo.

En un segundo cierre se retiraron `redhouse-user-receipt-20261113` y `redhouse-reauth-20261113`, también con `git worktree remove` sin forzar. Ambos estaban limpios; sus únicos archivos ignorados eran cachés Python/pytest/Ruff, y los agentes confirmaron que su trabajo activo estaba en el checkout principal. `git cherry` confirmó la integración de `ff05df9` y de ocho de los nueve commits del checkout de seguridad. El restante, `a3dcb34`, se cotejó con `62f66ea`: cuarenta de sus 41 archivos eran idénticos y `check_real_scanner.py` solo difería en formato, con AST idéntico. No se descartó código exclusivo. Ramas y commits se conservan; `git worktree list --porcelain` confirmó que solo queda el checkout principal. No se midió ahorro físico ni se retiraron datos, respaldos o herramientas.

El 13 de noviembre, tras finalizar las compilaciones móviles, se identificó como inactivo el daemon de `GRADLE_USER_HOME=/private/tmp/redhouse-gradle-home` y se cerró con `gradlew --stop`: un daemon y su hijo Kotlin propios; no otros procesos Java. Antes del cierre sumaban aproximadamente 3,1 GiB de RSS en una observación. Esto no prueba la causa del fallo de carga ni representa memoria física exclusiva.

Se retiraron cinco cachés iOS temporales reconstruibles de `/private/tmp`: `redhouse-ios-current-module-cache`, `redhouse-ios-e1f0957-module-cache`, `redhouse-ios-final-module-cache`, `redhouse-ios-module-cache` y `redhouse-ios-native-calendar-module-cache`. Se comprobó propietario, directorio real, ausencia de enlaces y contenido exclusivamente `.swiftmodule`, `.pcm` y `.timestamp`: 1.231 archivos, 286.268.130 bytes lógicos. El agente móvil confirmó que estaban inactivos y que el siguiente enlace usa otro caché. Se conservaron las aplicaciones firmadas, logs, xcresult, capturas, SDK, AVD, perfiles y datos. No se equipara el tamaño lógico con ahorro físico medido.

Se usó el instalador de skills existente con referencias Git fijas. La copia temporal revisada y la instalación coinciden por SHA-256 en sus 75 y dos archivos, respectivamente. Huellas de `SKILL.md`: `14f43337edfbf7822e091428e4ae0c6f92f86e3353deda6a30f6613121e2cf2d` y `d91970639e9f5c37682ac7ab60094d35f1c7c1f38d731bd56396563aee10c1d3`. La revisión incluyó instrucciones, entrada del buscador e importaciones/operaciones de los módulos de búsqueda; no constituye una auditoría exhaustiva del paquete. Las consultas usadas son locales, con Python estándar; no se instalaron CLI npm ni dependencias en las aplicaciones. La primera consulta del catálogo falló por el almacén de certificados del Python general; se repitió con el CA de certifi existente, manteniendo la validación TLS.

Criterio de aplicación: conservar la identidad roja y las decisiones del producto. Donante: campañas como contenido principal y próxima cita clara. Transportista: mapa, tarea asignada y siguiente acción. Escritorio: proceso interno, selección legible, confirmación y recuperación de operaciones. Sin dirección de gateway ni jerga de infraestructura en el login. Las recomendaciones se adaptan a Compose Multiplatform y PySide6; la skill no contiene una guía específica de PySide6 y sus ejemplos web no justifican cambiar frameworks.

La consulta `nonprofit donation mobile --design-system` devolvió una landing genérica azul/naranja; se descartó como diseño del móvil. La búsqueda explícita `charity donation --domain product` sí identificó el tipo de organización, pero su patrón de landing y panel de donaciones monetarias tampoco se traslada a los flujos de sangre y órganos. Las búsquedas de blancos táctiles y estado/accesibilidad en Compose aportan criterios de revisión, no pruebas de cumplimiento. Las recomendaciones de Compose aluden a una versión distinta de la instalada: toda API concreta debe cotejarse con las dependencias reales del proyecto.

La aceptación exige inspeccionar pantallas renderizadas y recorrer acciones, cancelación, errores, foco y texto ampliado. Contraste o geometría calculados solo complementan esa inspección. La instalación de estas herramientas no cierra UI/UX ni las etapas 04/05: el calendario nativo iOS dentro de un diálogo Compose fue rechazado visualmente por superposición y sigue en corrección. Los agentes de móvil y escritorio recibieron y leyeron ambas guías.
