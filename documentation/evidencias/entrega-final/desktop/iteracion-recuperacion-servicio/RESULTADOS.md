# Caída y recuperación de cobertura

El ensayo Qt/XML `ensayo-real` pasó 1/1 en 42,08 s con cuentas y datos sintéticos. Personal médico consultó una propuesta persistida; se detuvo el servidor local de Priorización del fixture. El proxy recibió el fallo y devolvió una respuesta HTML de error. La ventana mostró un mensaje, limpió los resultados anteriores y volvió a habilitar los controles; un evento Qt también se procesó. Tras restaurar el mismo servicio en el mismo puerto, «Actualizar» recuperó la propuesta; se comprobó el rol y la existencia de una sola fila en PostgreSQL. La sesión propia se revocó y el fixture cerró sus procesos. El diario usó clave efímera y directorio de prueba, sin llavero habitual.

Las tres capturas reales se inspeccionaron y están en `ensayo-real/`. El mensaje capturado decía «Verifica conexión y formato del servicio», expresión técnica poco útil. Después del ensayo se cambió solo el texto a «Comprueba tu conexión o contacta a soporte institucional»; la captura real y sus huellas corresponden a la versión anterior. `fuentes-texto-ajustado.sha256` identifica el texto posterior. La captura `texto-doble/error-ajustado-final.png` muestra el mensaje nuevo completo y legible con `ContractError` sintético, sin sesión ni red; se inspeccionó por separado. No se repitió el laboratorio por este cambio; se verificó sintaxis.

Alcance: caída controlada de un listener WSGI local y recuperación de una consulta en el fixture con proxy Flask/TLS y servicios en modo `TESTING`; Qt se renderizó en `offscreen`. No acredita fallos de infraestructura productiva, todas las operaciones ni que la GUI mantenga interactividad durante cualquier latencia prolongada. No se modificaron servicios ni reglas de negocio.
