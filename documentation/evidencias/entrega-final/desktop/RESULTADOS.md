## Reserva asincrónica y recuperación

La ejecución ampliada del laboratorio terminó con **1 aprobado y 1 fallido** en 134,44 s. La prueba fallida sí alcanzó solicitudes, evaluación, detalle, candidato y dictamen humano; recibió 202 de reserva. El fallo fue una aserción incorrecta del cliente de prueba que esperaba una reserva directa en vez del objeto de operación. No se declara reserva completada ni se ejecutó de nuevo por prioridad de recursos del AVD. La UI ahora distingue operación pendiente, completada y fallida.

Se añadió diario local cifrado para la reserva: persiste cuerpo, clave de idempotencia y ámbito antes de enviar; tras respuesta guarda ID y estado de operación. Tras pérdida de respuesta y reinicio, una cuenta autenticada en el mismo servidor e institución puede recuperar con el mismo cuerpo y clave. La clave de cifrado usa el almacén seguro del sistema; sin este, la reserva se bloquea. No guarda JWT. Se permiten solo backends nativos de macOS y Windows; Linux queda bloqueado hasta una implementación y prueba de almacén seguro. Un candado huérfano bloquea el diario hasta revisión manual. La integración real con Keychain/Credential Locker y la recuperación tras fallo del servidor siguen pendientes. En esa versión inicial ninguna otra escritura disponía del diario durable.

Dependencias: [Keyring 25.7.0 y backends de sistema](https://keyring.readthedocs.io/en/stable/), [Fernet, cifrado autenticado](https://cryptography.io/en/stable/fernet/). En macOS, el acceso de Keychain puede compartirse entre programas que usen el mismo ejecutable Python según configuración del sistema; debe revisarse al distribuir el paquete.

Paquete Mac: un primer intento falló por caché PyInstaller fuera del sandbox. Se corrigió el script para usar caché local y una compilación posterior produjo `apps/desktop/dist/RedHouse.app`. Ese artefacto es **anterior** a las modificaciones de solicitudes, transporte y diario; no se ha probado su arranque ni representa el código vigente. El script Windows existe y no se ejecutó. El empaquetado actualizado, firma y distribución siguen pendientes.

La suite local posterior pasó **10/10**: contratos, límites XML, una rotación concurrente simulada, selección sin escritura, roles y recuperación del diario con la misma clave. La primera prueba UI de recuperación falló porque la referencia al worker se perdía; tras conservarla, se repitió y pasó, seguida de la suite completa. No acredita servidor, Keychain ni ejecución en Windows.
